# 《语灵》独立应用方向 V1

状态：`PLATFORM DIRECTION CONFIRMED / ENGINE RECOMMENDATION PENDING USER FREEZE`

日期：2026-09-01

## 用户最新决定

《语灵》不再以微信小游戏为目标，改为真正可安装的独立游戏应用。用户接受开发、签名、审核与发行手续更复杂，优先追求角色美术、动作、镜头、材质和特效的表现空间。

纯游戏方向不变：语灵收集、探索、故事、进化、一次一只语灵出战、顺序回合战斗；希望形成收入，同时让玩家开心、舒适、有耐心。

## 推荐技术方向

当前推荐：`Unity 6 + URP`，第一目标平台按既有移动产品语境暂定 `iOS + Android`，未来可评估 PC。

原因：

- URP同时覆盖移动端与更高性能平台，可建立分档画质，而不是把美术上限锁死在小程序运行环境。
- Unity的角色、骨骼、Timeline/Cinemachine、粒子、Shader Graph、Addressables与移动端构建工具更适合中小团队做收集型3D回合RPG。
- 相比Unreal，Unity更适合当前偏移动、回合制、角色收集的规模；Unreal可提供更高桌面端渲染上限，但移动端需要更重的性能、包体与工程治理。若未来明确首发PC/主机，再重新比较。
- Cocos/Three.js仍可做轻量原型，但不再作为追求完整3D角色生产与原生发行的首选底座。

Unity不是自动提升质量的按钮。真正的美术上限仍取决于：角色三视图 → 高模/雕刻 → 拓扑 → UV与材质 → 骨骼与表情 → 动作 → 技能特效 → 灯光与镜头 → 真机优化。

## 迁移停止线

本裁决只改变平台方向，尚未授权：

- 创建Unity或Unreal正式工程；
- 搬迁、删除或重写现有网页仓库；
- 批量制作三只语灵、场景或技能；
- 采购资产、外包、开通开发者账号或支付发行费用；
- 承诺正式上线日期、设备范围或最终画质。

现有 `/prototype/battle-ui` 和 `/prototype/battle-3d` 继续保留，分别作为2D交互历史证据与3D构图/演出反例参考。程序化块模不继续打磨，也不作为角色生产资产。

## 正确的第一份上限样片

只做一只澜歌、一个水音技能、一个守门人受击目标：

1. 先补澜歌正/侧/背与材质说明，确保3D仍是原角色；
2. 完成一只有正式轮廓、脸、服装层次和手绘材质的游戏精模；
3. 建立基础骨骼、待机、吟唱、释放、收势；
4. 在Unity真实运行场景中完成水音镜头、光影、特效和受击；
5. 在目标手机上记录画质、帧率、内存、温升和包体；
6. 用户先裁决“想不想拥有这只语灵、上场是否过瘾”，再决定是否量产。

具体面数、贴图尺寸、目标帧率、最低设备与样片工期必须在引擎冻结后另立任务，不在本文件猜测。

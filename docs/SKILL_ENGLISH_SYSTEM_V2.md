# 《语灵》技能 × 英语系统 V2

状态：`FROZEN / APPROVED FOR PROTOTYPE IMPLEMENTATION`

更新时间：2026-08-27

本文件是战斗技能与英语调用的当前权威规格。Codex 在修改任何战斗、技能、英语调用、技能倍率或战斗取词逻辑前，必须先读本文件。若旧代码、Review A、历史文档与本文件冲突，以本文件为准。

## 1. 核心契约

> **技能决定这一回合“做什么”；英语决定这件事“这次发挥多少”。**

必须严格分开两层：

- **世界教学层**：词义必须与世界事件/动作自然对应，用真实语境把词教会。
- **战斗调用层**：词不再与具体技能语义绑定。战斗只调用玩家已经真正学过、具备战斗资格的词。

因此：

- `water` 可以被「水音」调用，也可以被「回潮」调用；
- `help` 也可以被不同技能调用；
- 不能因为词义不同改变技能本身的职责；
- 不建立“某个词只能服务某个技能”的固定词池。

Review A 中“`Used + battleEligible + 与技能/行动语义匹配`”这一条在**战斗层**被本 V2 覆盖。世界教学仍然要求语义自然；战斗取词只要求：

`Used + battleEligible`

## 2. 战斗取词规则

普通战斗中的英语调用必须满足：

1. 词已达到 `Used`；
2. 词已被标记为 `battleEligible`；
3. 词来自正式 5505 Excel 真源；
4. 不得出现未教过的新词；
5. 玩家选择技能后，再由系统从合格池取词；
6. 技能选择不能反向决定“只能抽某类词”；
7. 合格池大于 1 时，优先避免连续两回合重复同一词；只有一个合格词时允许重复。

“玩家可直接挑战”只表示不强制做额外训练，不代表允许战斗首次教授陌生词。

## 3. 英语调用质量

即时战斗只使用以下三档。**不得用答题速度直接惩罚零基础玩家。**

| 本次调用状态 | `qualityMultiplier` |
|---|---:|
| 无帮助独立正确 | `1.00` |
| 使用轻度支架后正确 | `0.70` |
| 错误 / 依赖完整答案后完成 | `0.40` |

规则：

- 反应时间可以后台记录，但 V2 原型中不直接改变技能数值；
- 所有倍率必须配置化；
- `1.00 / 0.70 / 0.40` 是当前 V2 原型冻结初值，Codex 无权自行调整；
- 答错不得统一等于“失去行动”或 `0%`；
- 不同技能不得再拥有各自独立的“答错倍率”；统一使用本表。

## 4. 技能数值结算规则

每个技能必须由**明确的技能配置**定义自己的效果。`executionKind` 只允许用于分类、UI、动画或逻辑路由，**不得再由 `executionKind` 自动推断基础伤害/回复/护盾数值**。

没有显式 `skillEffectConfig` 的技能视为规格缺口：报告 `PENDING_K3`，不得猜数值。

英语倍率只缩放技能的**正向数值效果组件**，不改变技能身份。

例如：

- 「回潮」永远是“伤害 + 回复”；
- 「护芽」永远是“伤害 + 护盾”；
- 「焰尾」永远是爆发技能；
- 不能因答错让「回潮」突然只剩攻击，或让「水音」变成治疗。

结构性成本/限制（如冷却、一次性消耗）不因英语质量减免。

## 5. 九个初始技能：V2 原型冻结效果

以下为 V2 原型唯一允许实现的基础效果。数值全部配置化，但当前实现必须按本表，不得擅自平衡。

| 语灵 | 技能 | 战斗职责 | V2 原型基础效果 |
|---|---|---|---|
| 芽语 | 叶拍 | 稳定输出 | `24` 伤害 |
| 芽语 | 护芽 | 保护 | `8` 伤害 + `24` 护盾 |
| 芽语 | 扎根 | 防御 | 下一次受到伤害降低 `40%` |
| 烬尾 | 火星 | 稳定输出 | `24` 伤害 |
| 烬尾 | 焰尾 | 爆发 | `40` 伤害；使用后 `1` 回合不可再次使用 |
| 烬尾 | 蓄火 | 准备爆发 | 下一次伤害技能额外提高 `60%`，触发后消耗 |
| 澜歌 | 水音 | 压制 | `18` 伤害 + 敌方下一次伤害降低 `20%` |
| 澜歌 | 回潮 | 续航 | `10` 伤害 + 恢复 `22` 生命 |
| 澜歌 | 静波 | 稳住局面 | 恢复 `10` 生命 + 下一次受到伤害降低 `30%` |

### 5.1 倍率示例

只用于说明结算，不新增正式文案。

- 「回潮」100%：`10` 伤害 + `22` 回复；
- 「回潮」70%：伤害与回复分别乘 `0.70` 后按统一取整规则结算；
- 「回潮」40%：伤害与回复分别乘 `0.40`；
- 「扎根」70%：减伤比例为 `40% × 0.70 = 28%`；
- 「蓄火」40%：下一次伤害技能额外提高 `60% × 0.40 = 24%`。

同一技能的所有正向数值组件使用同一个 `qualityMultiplier`。

## 6. 技能选择必须形成真实战术差异

### 芽语

- 叶拍：想直接输出时选；
- 护芽：需要伤害 + 护盾时选；
- 扎根：预判下一次伤害较高时选。

### 烬尾

- 火星：稳定输出；
- 焰尾：高爆发，但不能连续使用；
- 蓄火：牺牲当前直接输出，为下一次伤害技能做准备。

### 澜歌

- 水音：更偏向压低敌方压力；
- 回潮：掉血后用较低输出换取续航；
- 静波：同时补一点生命并降低下一次承伤。

第一轮验收不增加 DOT、复杂控制链、元素克制、技能资源条等新机制。若技能差异仍不明显，优先调当前配置数值，不新增系统。

## 7. 战斗中的完整操作顺序

每回合：

1. 玩家看到当前真实已解锁技能；
2. 玩家先选择技能；
3. 当前技能区域内展开本次英语调用；
4. 系统从 `Used + battleEligible` 池取词；
5. 玩家完成英语调用，可使用当前允许的支架；
6. 根据 `qualityMultiplier` 计算技能全部正向效果；
7. 技能立即执行并显示实际伤害/回复/护盾/减伤结果；
8. 敌人行动；
9. 回到技能选择。

禁止：

- 跳转到独立“英语考试页”；
- 先出英语题再让玩家选技能；
- 因词不同改变技能类型；
- 因错误直接跳过整回合。

## 8. 战斗反馈

反馈核心是“技能发生了什么”，不是“英语考了多少分”。

允许显示系统结果，例如：

- 技能名；
- `100% / 70% / 40%` 发挥；
- 实际造成伤害；
- 实际回复；
- 实际护盾/减伤。

禁止使用刺眼的 `WRONG` 作为主要反馈。

正式技能表现文案、剧情口吻、动画描述只复用已冻结正式内容；没有正式内容时使用 `PENDING_K3`，Codex 不得自行创作。

## 9. 战后薄弱词与针对训练

- 战斗只记录本次真实暴露的薄弱词；
- 如果存在薄弱词，可进入短针对训练；
- 针对训练负责重新解释/修复，不只是原题再问一遍；
- 训练后立即再挑战；
- 已产生学习证据不回滚；
- 如果没有真实薄弱词，不伪造英语问题。

## 10. 与当前 V1 代码的冲突处理

当前代码中以下逻辑属于 V1 历史实现，V2 实现时必须明确迁移，不得继续作为权威：

- 按 `executionKind` 自动决定基础伤害；
- 不同 `executionKind` 使用不同失败倍率；
- `skillEffects`、`spirit-config.effect` 与实际结算存在多套解释；
- `hesitant` / 反应时间直接参与即时伤害的任何潜在逻辑；
- 战斗层“技能语义匹配词”的限制。

迁移完成后必须只有一个数值真源：**V2 `skillEffectConfig`**。

## 11. Codex 禁止自行发挥

Codex 不得：

- 自行改技能定位；
- 自行增加/删除技能效果组件；
- 自行调整 V2 原型数值；
- 自行修改 100/70/40；
- 自行决定某个词只能绑定某个技能；
- 自行新增正式技能描述或演出文案；
- 自行因为“平衡”引入新资源、状态、元素、冷却体系或成长规则。

遇到缺口必须停下并报告，正式内容用 `PENDING_K3`。

## 12. V2 首轮验收

最小验收重点：

1. 同一技能连续两回合可以调用不同合格词；
2. 不同技能也可以调用同一个合格词；
3. 玩家明显感到技能选择本身有战术差异；
4. 英语质量只改变“发挥多少”，不改变技能身份；
5. 满血与受伤状态下，澜歌「水音 / 回潮」能自然产生不同选择倾向；
6. 答错仍能行动，但稳定正确明显更高效；
7. 直接挑战不出现未教过的新词；
8. 不修改 EP01–EP03 冻结剧情，不新增词、敌人、关卡、成长系统。

本规格通过前，不允许 Codex 自行解释或补全技能系统。

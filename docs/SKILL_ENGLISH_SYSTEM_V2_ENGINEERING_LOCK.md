# 《语灵》技能 × 英语系统 V2：工程补充裁决

状态：`FROZEN / APPROVED FOR PHASE-A MIGRATION`
更新时间：2026-08-27

本文件补齐 `docs/SKILL_ENGLISH_SYSTEM_V2.md` 尚未明确的工程语义。两份文件共同构成 V2 当前权威规格；若两者出现冲突，以本文件的较新裁决为准。

## 1. 战斗取词：正式覆盖 Review A 旧规则

战斗层取词条件固定为：

`Used-or-Maintained + battleEligible`

**不再要求“与技能/行动语义匹配”。**

- 世界教学层仍必须语义自然；
- 战斗层不建立技能专属词池；
- 同一技能可以连续调用不同合格词；
- 不同技能可以调用同一个合格词；
- 玩家先选技能，再确定本次调用词。

任何仍写着 `Used + battleEligible + 与技能/行动语义匹配` 的旧规则均已被 V2 覆盖。

## 2. `Maintained` 的正式语义

`Maintained` 不是绕过 `Used` 的另一条通路，而是 **词已经达到 `Used` 之后，后续维护成功的证据状态**。

因此：

- `Introduced / Guided / Retrieved` 不能进入战斗池；
- `Used + battleEligible` 可以进入战斗池；
- `Maintained + battleEligible` 也可以进入战斗池；
- 一个词不得在从未达到 `Used` 的情况下直接进入 `Maintained`；
- V2 Phase A 不因答题速度撤销 `battleEligible`；
- 维护失败不自动创造新的系统或降级规则，本阶段不扩展动态资格回收机制。

## 3. 统一取整规则

所有战斗数值使用以下统一规则，Codex 不得逐技能自行决定。

### 3.1 整数型效果

伤害、回复、护盾等最终以整数表示的组件：

1. 先应用该组件本回合所有倍率；
2. **最后只取整一次**；
3. 使用 JavaScript `Math.round` 的正数规则。

例如：

- `22 × 0.70 = 15.4 → 15`；
- `24 × 0.70 = 16.8 → 17`；
- `18 × 0.70 = 12.6 → 13`。

禁止先把中间倍率取整，再继续计算。

### 3.2 百分比型效果

减伤、削弱、蓄火加成等百分比：

- 逻辑层保留小数，不做中间整数化；
- UI 如需显示百分比，可 `Math.round(ratio * 100)`；
- 最终造成的整数伤害只在所有百分比结算完成后取整一次。

例如：

- 「水音」70%：`20% × 0.70 = 14%`；
- 「扎根」70%：`40% × 0.70 = 28%`；
- 「蓄火」70%：存储下一次伤害加成 `60% × 0.70 = 42%`。

## 4. 没有合格词时的直接挑战

“玩家可以直接挑战”表示 **不强制战前训练**，不是允许绕过已有英语调用。

### 4.1 有合格词

只要当前存在 `Used-or-Maintained + battleEligible` 词：

- 即使玩家选择“直接挑战”，战斗仍按 V2 正常进行英语调用；
- 不允许通过“直接挑战”按钮绕开已经具备资格的英语。

### 4.2 完全没有合格词

只有当合格词池为 0 时，才进入 `no-call` 兜底：

- 仍显示并使用玩家真实技能；
- **不得创造“基础技能 20 伤害”等临时技能**；
- 不出现陌生英语；
- 本回合不产生薄弱词；
- 技能所有正向数值组件使用独立配置的 `noCallMultiplier`；
- V2 Phase A 原型冻结：`noCallMultiplier = 0.40`；
- `noCallMultiplier` 与“答错 0.40”数值当前相同，但语义和配置键必须分开，后续可以独立调整。

Phase A 测试战斗必须保证：在 `noCallMultiplier = 0.40` 下，至少存在一种合理的真实技能选择路径可以取得胜利；否则“直接挑战”会变成伪入口。

## 5. V2 统一战斗结算顺序

Phase A 只迁移融合切片中的「水音 / 回潮」，但结算顺序先锁死，避免实现方自行决定。

### 5.1 玩家阶段

1. 玩家选择当前真实技能；
2. 系统确定本次调用方式：
   - 有合格词：英语调用得到 `qualityMultiplier = 1.00 / 0.70 / 0.40`；
   - 无合格词：不出英语，使用 `noCallMultiplier = 0.40`；
3. 按技能显式配置计算所有正向组件；
4. 同一技能的正向组件使用同一个本回合倍率；
5. 将该技能的本回合组件**作为一次技能结算整体应用**：
   - 伤害扣减敌方 HP；
   - 回复立即恢复己方 HP，最高不超过 Max HP；
   - 护盾立即增加；
   - “下一次敌方行动减伤/削弱”等状态立即挂载；
6. 若技能结算后敌方 HP 已为 0：立即胜利，**本回合敌人不再行动**。

若未来迁移「蓄火」：施放时保存 `baseBonus × 当次英语倍率`；下一次真实伤害技能以 `baseDamage × 当次技能英语倍率 × (1 + 已保存加成)` 计算，最后取整一次，并在触发后消耗。Phase A 不实现该技能。

### 5.2 敌方阶段

敌方仍存活时：

1. 读取敌方原始伤害 `rawDamage`；
2. 先应用敌方受到的“下一次伤害削弱”（如水音）：`rawDamage × (1 - weaken)`；
3. 再应用己方“下一次受到伤害减免”（如扎根/静波）：`× (1 - mitigation)`；
4. 百分比处理完后，对本次待承受伤害 `Math.round` 一次；
5. 护盾先吸收该整数伤害；
6. 剩余伤害再扣 HP；
7. 一次性“下一次行动/下一次伤害”状态在本次结算后消耗；
8. HP 归 0 才判负，否则进入下一回合。

百分比削弱与百分比减伤若未来同时存在，按上述顺序乘算；本阶段不新增同类状态叠加规则。若后续出现同类叠加需求，必须重新 Review，不得自行做相加、取最大值或叠乘。

## 6. Phase A 工程迁移范围

本轮**只迁移独立融合切片**，不迁移主线全局战斗。

原因：先验证“技能选择差异 × 英语发挥倍率”是否在手机实机中成立，再决定是否把 V2 接入九技能与主线。

### 允许触碰

- `app/game/fusion-slice.ts`
- `app/prototype/fusion-slice/page.tsx`
- 必要时新增一个 V2 纯配置/纯结算模块，但本轮只能被融合切片引用
- 与 Phase A 直接相关的新 validator
- `package.json` 中仅新增对应 validator script
- Phase A 工程交接文档
- 若布局确有必要，可最小修改原型专用样式；不得借机改主站表现

- `app/game/bridge-config.ts`

V2 九技能表仍是未来全局迁移的设计真源，但 **Phase A 不得把另外七个技能接进运行时**。

## 7. Phase A 两个技能的冻结效果

只使用 V2 已冻结值：

- 「水音」：`18` 伤害 + 敌方下一次伤害降低 `20%`；
- 「回潮」：`10` 伤害 + 恢复 `22` HP。

对应三档示例（按本文件取整规则）：

### 水音

- 100%：`18` 伤害 + `20%` 削弱；
- 70%：`13` 伤害 + `14%` 削弱；
- 40%：`7` 伤害 + `8%` 削弱。

### 回潮

- 100%：`10` 伤害 + `22` 回复；
- 70%：`7` 伤害 + `15` 回复；
- 40%：`4` 伤害 + `9` 回复。

`no-call` 也使用 0.40 的技能发挥，因此仍保持技能身份：水音走 `7 + 8%削弱`，回潮走 `4 + 9回复`，而不是统一变成临时基础攻击。

## 8. Phase A 取词确定性

为了让实机和自动回归可重复，本轮不使用随机取词。

- 词池仍只使用当前融合切片已批准的正式词；
- 取词与技能无关；
- 新战斗从合格池第一个词开始；
- 后续回合轮换并优先避免连续重复；
- 因此在当前两词原型中应能稳定验证：
  - 连续两回合选「水音」：本次调用可从 `water → help`；
  - 重新开始战斗，第一回合选「回潮」：同样可先调用 `water`。

这只是 Phase A 的确定性验证策略，不冻结未来正式战斗的长期抽词算法。

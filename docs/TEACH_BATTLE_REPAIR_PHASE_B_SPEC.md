# 《语灵》Phase B：教学 → 战斗 → 补弱 → 再战连续体验

状态：`FROZEN / APPROVED FOR ENGINEERING TASK PREP`
日期：2026-08-27

本阶段只验证一件事：

> **玩家能否把“刚刚在世界里学会的英语”自然带进战斗；战斗暴露真实薄弱点后，只修复刚才的问题，并马上再战。**

Phase B 不进入主线，不扩系统，不新增正式内容。

---

## 1. 核心闭环

冻结流程：

`语灵站日常完成 → 直接进入测试战斗 → 暴露真实薄弱词 → 针对训练 → 立即再战`

目标不是增加功能，而是消除“教学原型”和“战斗原型”之间的拼接感。

Phase B 需要让玩家自然理解三件事：

1. 战斗里出现的词，是自己刚刚真正用过的词；
2. 战后只回来一个词，是因为刚才就是这个词没有稳定调用；
3. 修复后马上再战，同一个词再次出现时，技能发挥应明显更顺。

---

## 2. 不改变的冻结底座

Phase B 继续沿用 V2，不重新设计：

- 技能决定“做什么”；英语决定“发挥多少”；
- 战斗取词：`Used-or-Maintained + battleEligible`；
- 战斗层不按技能语义分词；
- independent / supported / failed = `1.00 / 0.70 / 0.40`；
- no-call 使用独立 `0.40`；
- 反应时间不影响即时战斗倍率；
- 水音 / 回潮 Phase A 数值与结算顺序不变；
- 正式 5505 Excel 仍是词汇唯一真源；
- 当前只使用已经批准进入融合切片的正式词，不新增任何词。

Phase B 不得因为“连接体验”而改写 Phase A 战斗规则。

---

## 3. 连续体验结构

### 3.1 语灵站日常完成

保留现有教学内容与学习证据逻辑。

Phase B 的连续路径中，玩家完成最后一个真实行动后：

- 保留一个短暂完成停顿；
- **不再进入现有“教学总结页 → 再点链接 → 融合切片菜单”的两层中转**；
- 不展示开发者式的“几词 Used / battleEligible / 世界教学证据”诊断卡；
- 最多只保留一次自然的“继续”动作，然后进入战斗技能选择。

现有独立教学页的总结界面可保留给开发调试入口，但不得出现在 Phase B 主验收路径里。

### 3.2 进入战斗

进入的仍是 Phase A 已验证的独立测试战斗，不新增敌人或剧情。

连续路径中应隐藏或弱化仅面向开发者的标题，例如：

- `Learning × Adventure · V2 Phase A`；
- `世界教学证据`；
- `2/2 个测试词可进入战斗`；
- 其他会让玩家明显感觉“刚离开一个学习 Demo，又打开一个战斗 Demo”的诊断信息。

开发者信息可以在独立 debug 入口继续保留。

### 3.3 第一次战斗调用的因果提示

玩家仍然先选技能，再出现英语调用。

为了让玩家理解“为什么这个词会在这里出现”，第一次来自语灵站日常的英语调用允许增加一个**一次性、轻量、非技术化**提示：

> `刚才用过`

它只用于首次建立因果，不长期常驻。

禁止玩家侧显示：

- `Used`；
- `Maintained`；
- `battleEligible`；
- `word pool`；
- `evidence`。

这些只属于后台/开发信息。

---

## 4. 战斗暴露薄弱点

Phase B 不重新定义 Phase A 的英语发挥倍率。

本阶段只要求：

- 战斗中的非稳定调用必须来自玩家刚才真实发生的调用；
- 不生成与本场无关的薄弱词；
- 同一个 `wordId` 在一场战斗里只需要进入一次针对训练，不重复刷同一词；
- 没有真实薄弱词时，战后直接结束，不伪造针对训练。

Phase B 主验收路径至少要覆盖一次 **failed = 40%**，以验证“答错 → 补弱 → 再战”的完整因果。

`supported = 70%` 的既有记录规则本阶段不强行重构；如实机发现“用了轻提示但仍被强制补弱”明显造成不适，再单独 Review，不让 Codex自行更改标准。

---

## 5. 针对训练：只修刚才的问题

针对训练必须保持极短，不变成第二个学习页。

每个真实薄弱词只走以下最小两步：

1. **重新建立意义**：复用正式词源已有单词与中文义项，不新增例句、不新增词义、不新增解释体系；
2. **再独立确认一次**：收起直接答案，让玩家自己完成一次提取。

如果再次错误：

- 回到同一个词的重新建立意义；
- 再试一次；
- 不增加新题型，不塞其他词。

针对训练成功只表示“这个刚才暴露的问题已经重新确认”，不因为一次短训练就私自提高长期 Mastery、星级或成长状态。

Phase B 不新增新的学习状态枚举。

---

## 6. 为什么只复习这个词

战后不要显示课程式错题列表或全词复习入口。

玩家只需要看到本场真实暴露的词。

推荐最小信息结构：

- 本场哪个词还需要帮助；
- 该词刚才对应的技能发挥百分比；
- 一个进入针对训练的主按钮。

系统表达必须保持中性，不使用刺眼 `WRONG`，也不评价“英语差”。

正式剧情/角色对白不在 Phase B 新增；缺正式内容使用 `PENDING_K3`。

---

## 7. 针对训练 → 立即再战

完成本场所有真实薄弱词的短训练后：

- 不返回教学菜单；
- 不返回融合切片入口；
- 不再展示课程总结；
- 直接进入同一测试战斗的新一轮挑战。

“同一场战斗”指：

- 相同技能配置；
- 相同敌人配置；
- HP 按一次新挑战正常重置；
- 不回滚已经产生的学习证据。

为了让修复效果足够快地被玩家感知，当前两词原型中，刚修复的词必须在再战前 **2 次英语调用以内**重新出现。

不要求强制成为第一题，也不修改未来正式抽词算法；Phase B 继续利用当前确定性两词轮换完成验证。

如果玩家这次独立正确，应直接从技能实际结果看到 100% 发挥；不额外弹“进步报告”。

---

## 8. 体验连续性的 UI 原则

Phase B 的重点不是换皮，而是减少模式切换感。

连续路径必须做到：

- 教学结束后最多一次继续操作进入战斗；
- 不经过第二个原型首页；
- 不出现开发诊断卡；
- 战斗调用仍在技能区域内展开；
- 战后补弱仍处于同一连续流程，不需要重新导航；
- 补弱完成后直接再战；
- 不新增正式动画。

允许：

- 现有轻量淡入/位移/状态切换；
- 一个很短的过渡停顿；
- 原型专用最小 CSS 调整。

禁止：

- 正式技能动画；
- 新 CG；
- 新场景资产；
- 新演出系统。

技能动画已在 Phase A Sol 验收中明确后移。

---

## 9. Phase B 主验收路径

至少完整走一次以下路径：

1. 从语灵站日常的开始进入；
2. 正常完成教学事件；
3. 最后真实行动结束后，不经过教学总结页和融合切片菜单，直接进入战斗；
4. 第一场战斗中故意让其中一个已学词 failed；
5. 战斗结束后只出现本场真实薄弱词，不出现无关词；
6. 针对训练只处理该词；
7. 完成重新建立意义 + 一次独立确认；
8. 不回菜单，立即进入再战；
9. 被修复词在前 2 次英语调用以内重新出现；
10. 这次独立正确时，技能直接以 100% 发挥，玩家能从伤害/回复/削弱实际结果感受到改善；
11. 再战结束后不自动追加新的课程页。

还要单独走一次“第一战没有真实薄弱词”的路径：

- 战后应直接结束；
- 不出现假的针对训练。

---

## 10. Phase B 产品验收问题

实机 Review 不以“页面都能点通”为通过标准，而看下面五句话是否成立：

1. **“我没有感觉自己从学习页跳去了另一个 Demo。”**
2. **“战斗里这个词出现时，我知道它就是刚才用过的东西。”**
3. **“刚才卡住哪个词，战后就只回来哪个词。”**
4. **“复习完马上又碰到它时，我明显觉得这次更顺。”**
5. **“整个过程像一次连续经历，而不是学习 → 考试 → 错题本三个模块。”**

以上至少前四项必须明显成立，才允许讨论进入主线战斗迁移。

---

## 11. Phase B 必须记录的体验风险

只观察，不在本阶段扩系统解决：

1. 从世界教学切到战斗时，是否仍有明显“考试开始了”的感觉；
2. 第一次显示 `刚才用过` 是否足够建立因果，还是反而显得教学味重；
3. 战后短训练是否像“刚才的问题被修好”，还是像跳进错题本；
4. 再战是否真正更顺，还是只因为玩家记住了刚才选项位置；
5. supported 70% 是否也进入补弱会造成不必要打断；
6. 同一词在短时间内再次出现，是否像自然再使用，还是像机械重考。

这些问题必须通过实机判断，Codex 不得自行扩大设计处理。

Phase B 实机通过后，才重新 Review 是否允许进入主线战斗迁移。

# 《语灵》成熟回合制战斗基线 Sol Review

状态：`RESEARCH COMPLETE / RECOMMENDATION ONLY / NO CODE AUTHORIZATION`

日期：2026-08-30

## 1. 本轮结论

《语灵》的学习冒险闭环没有走歪，但 Phase A–Candidate C 的战斗设计方法已经局部走偏：团队围绕统一倍率、敌伤与反馈毫秒数反复调参，却没有先选定一套成熟、可解释、真正产生决策的回合制骨架。

Candidate C 只保留为以下技术证据：

- 世界教学证据能够进入战斗；
- 战斗能够记录真实薄弱词；
- repair 后能够自动再战；
- 英语调用与技能执行能够在同一界面连续发生。

Candidate C **不代表正式战斗设计**。停止 Candidate D，不继续调 `25% / 14伤害 / 1.2秒`，不迁入主线。

## 2. 成熟案例真正值得借的部分

### Slay the Spire：先看敌人要做什么，再决定这一回合

成熟点不是卡牌数量，而是敌方意图公开。玩家在行动前知道敌人将攻击、强化、削弱或防御，因此“攻击、保护、回复、准备”产生真实选择。

对《语灵》的价值：水音、回潮、静波等技能不需要靠人为拉大数值来区分；只要敌方下一步清楚，玩家自然知道此刻为何选择压制、续航或防御。

### Sea of Stars：行动本身成立，额外表现争取更好的结果

该游戏采用无时间条的纯回合决策，玩家可以按自己的节奏选择；额外输入用于强化攻击、防御，并通过敌方蓄力的锁机制降低或阻止危险行动。

对《语灵》的价值：英语不必承担“发明战斗”的职责。玩家先做战术选择，英语稳定调用提供额外优势；零基础玩家可以思考，不受反应速度惩罚。

### Pokémon：少量技能、明确职责、状态与克制制造选择

成熟点是每回合从少量动作中选择，HP归零的胜负清晰；技能不只有伤害，还可造成状态、持续影响或承担战术职责。回合制允许玩家充分思考。

对《语灵》的价值：每只语灵保留少量、身份清楚的技能即可。趣味来自“什么时候用什么”，不是一次塞入大量系统。

### Honkai: Star Rail：基础行动与更强行动形成资源节奏

成熟点是普通行动和技能之间存在团队资源循环，敌人弱点与击破又提供阶段目标。

对《语灵》的价值：可作为未来中后期参考，但不适合作为零基础首个战斗骨架。它需要队伍、速度轴、资源点、弱点等多层系统，当前照搬会让学习与战斗同时过载。

## 3. 三套可选骨架

### 方案A：敌方意图 × 三技能应对（推荐作为第一版）

每回合：

1. 敌人公开下一步意图与预计结果；
2. 玩家从当前语灵的 3 个技能中选择；
3. 在技能区域完成一次已学词调用；
4. 技能结算；
5. 敌人按已公开意图行动；
6. 状态推进到下一回合。

英语处理采用成熟的“基础结果 + 掌握奖励”表达：

- 技能的基础职责始终成立；
- 独立正确获得完整强化或额外战术收益；
- 使用支架获得较小强化；
- 错误只得到基础结果，并记录薄弱词；
- 不是所有数值统一乘同一个倍率。

例：水音始终造成基础伤害；独立正确额外强化压制。回潮始终提供少量续航；独立正确才获得完整回复。具体数值与正式表现需另行冻结，Codex不得推断。

优点：

- 最少新增系统；
- 技能选择立刻有理由；
- 英语不会变成独立考试；
- 错误后果由玩家眼前的敌方意图自然放大；
- 适合手机和纯零基础玩家。

风险：敌人意图若过于固定，战斗会很快变成标准答案题；需要用敌人行动组合而非大量新规则制造变化。

### 方案B：敌方蓄势 × 打断/削弱

敌人的危险技能提前1–2回合公开。玩家正常使用攻击、保护、回复技能；稳定英语调用同时推进“打断/削弱”进度。未完成进度时敌人仍发动技能，但威力可部分降低。

优点：学习稳定度与战斗目标联系非常直观，成功调用有明确爽点，错误有清晰代价。

风险：容易把每场战斗都做成破条；如果英语正确只是机械填格，也会变成换皮答题。适合作为精英怪或Boss机制，不建议成为所有普通战斗的唯一骨架。

### 方案C：基础行动 × 技能资源循环

基础行动生成技能资源，强技能消耗资源；英语调用影响资源收益、技能附加效果或击破效率。

优点：长期构筑和多语灵队伍空间最大。

风险：对首章与零基础玩家过重，也会把验证范围扩成队伍、速度、资源和敌人弱点等多个系统。当前不采用，保留为中后期研究方向。

## 4. Sol推荐裁决

推荐采用：

> **方案A作为普通战斗骨架，方案B只作为精英/Boss的特殊机制；暂不采用方案C。**

这不是把 Slay the Spire 或 Sea of Stars 原样复制，而是使用已经被验证的设计职责：

- 敌方意图负责产生战术问题；
- 技能负责回答战术问题；
- 英语稳定调用负责奖励更好的执行；
- HP与状态负责清晰反馈；
- repair负责解决真实暴露的学习问题。

正式30秒循环建议为：

> 看见敌方意图 → 选择语灵技能 → 调用已学词 → 看到技能与敌方结果 → 调整下一回合

其中“好玩”的核心必须首先来自敌方意图与技能选择。即使暂时拿掉英语调用，战斗仍应具备基本决策；英语加入后应让执行更有成就感，而不是成为战斗存在的唯一理由。

## 5. 对现有V2的必要修正方向

现有V2中的以下内容可以保留：

- 先选技能，再调用英语；
- 战斗只取 `Used-or-Maintained + battleEligible`；
- 思考时间不直接惩罚；
- 技能与单词不固定绑定；
- 技能身份不因答错改变；
- 战斗暴露薄弱，repair负责解决。

需要重新Review、暂不继续冻结为正式方案：

- “英语质量统一缩放技能全部正向组件”；
- `100/70/40` 或 `100/70/25` 作为所有技能的统一答案；
- 普通敌人只会固定反击，玩家看不到下一步意图；
- 靠提高敌伤迫使玩家认真学习；
- 用固定毫秒数代替完整的战斗演出与可跳过节奏策略。

新的原则应是：

> **技能身份与基础职责来自战斗系统；英语质量决定明确、离散、可解释的掌握奖励。错误的代价来自错过优势并承受已预告的战局后果，而不是系统额外羞辱或统一砍成某个百分比。**

## 6. 下一步只做纸面战斗样机

在任何代码工作前，先完成一张不含正式剧情与对白的纸面战斗规格：

- 1只测试语灵；
- 3个职责不同的测试技能；
- 2类普通敌人意图；
- 1个精英蓄势意图；
- 6–8回合代表战斗记录；
- 独立正确、支架正确、错误各自的离散结果；
- 不新增资源条、元素克制、队伍速度轴、装备或成长系统。

纸面样机必须先回答：

1. 不放英语题时，这场战斗是否仍有选择？
2. 放回英语调用后，玩家是否更想稳定掌握，而不是只怕惩罚？
3. 同一个错误在攻击、保护、回复技能中是否有符合直觉的不同后果？
4. 玩家是否能在敌人行动前预测选择的风险？
5. 连续失败后，repair是否修复真实薄弱点而不是重复惩罚？

通过纸面Review后，才允许写新的独立战斗样机任务单。不得从Candidate C继续打补丁。
